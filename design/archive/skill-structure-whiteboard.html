The skill, structured

How the judgment layer is built so that atoms get drafted, scenarios get generated, runs execute, and results come back — with the agent never holding anything load-bearing in its head.

WHITEBOARD — disposable by design. This page exists to think against. Converged conclusions fold into 🧩 piece 5 and 📜, then this page is deleted. Open questions for Viswa are collected in §7.

1The one design law

Everything below follows from a single rule, bought with the scars of eight rows:

the law

The skill decides nothing a function could decide, and remembers nothing a file could remember. Every episode starts by reading state from disk and ends by writing artifacts to disk. The engine's --json outputs are the agent's senses; the model package and evidence ledger are its memory; conversation context is a scratchpad that can vanish at any moment (compaction, crash, session end) with zero loss.

Concretely, this kills the three historical failure modes: prose rules silently dropped in rewrites (now: gates are engine functions), the agent's stop-feeling ("model exhausted") ending runs early (now: only zero-debt | budget stops, computed), and steering state lost across compaction (now: the dispatcher re-derives everything from disk each episode).

3The dispatcher: four episodes, mechanical preconditions

Each wake, SKILL.md runs one pass: call wio harness status --json, match the FIRST true precondition top-to-bottom, run that one episode, write its artifact, end. Priorities are fixed; the agent never chooses between eligible episodes.

1 · RED episodeprecondition: status.uncrystallized_reds > 0
The engine has already reproduced and shrunk (deterministic re-runs — no judgment needed). The skill's job is what remains: classify (product bug / harness bug / infra gap — via the red-triager brief + source reading), write the finding (finding-writer brief: minimized composition, replay recipe, severity, neighbors) and pass the promotion gates (control evidence attached by the engine; red-proof verified; reviewer verdict). Exit artifact: evidence/findings/<key>.md as a draft finding, or a refutation note that reverts the red.
2 · MODEL episodeprecondition: status.model_debt > 0 (orphan surfaces · refuted parks · contradiction flags · first run ever)
The only place deep intelligence is spent. Sub-flows by trigger: initial draft (read docs/exports/code → write atoms + resources + invariants, every claim cited); orphan surface (census floor found a documented API with no flow → draft its atom or park with evidence); refuted park (park-refuter killed a park → draft the atom it was hiding); contradiction (a run observed something the model says is impossible → fix the model, version-bump). Every output passes the atom-critic (false invariants? missing checkpoints? under-declared resources? — lint catches the mechanical cases first) and lands as a digest for ratification. Exit artifact: model diff + digest; officials never run against unratified model changes.
3 · EXECUTE episodeprecondition: status.owed_cells > 0 && status.budget_remaining > 0
One command — wio harness run --budget <chunk> — and the engine does everything: selects eligible cells, materializes scenarios + controls, dispatches to the bench, evaluates oracles, appends evidence, updates cell states. The skill monitors and reacts: a blocked cell → write the named infrastructure obligation (and continue); a near-miss/divergence flag → add a coupling hypothesis to the model queue; harness friction → friction.md. It does NOT pick cells, order work, or interpret greens. Exit artifact: the engine's run report + any obligations/hypotheses filed.
4 · STOP episodeprecondition: status.owed_cells == 0 || status.budget_remaining == 0
Render the honest stop report from engine state (never from feeling): debt paid vs remaining, blocked obligations, findings tally, budget spent. If zero-debt: the loop idles until the model changes or new commits land. Exit artifact: stop report; ntfy/PR-comment as configured.

4The choreography: from nothing to results, who does what

The full pipeline with every hand-off explicit — skill = judgment (tokens) · engine = deterministic functions (free) · bench = metered execution · human = ratify/promote only:

skill
MODEL episode: drafts model/flows/*.py + resources.py from docs/code, cited; atom-critic challenges; digest rendered
human
ratifies the digest (or edits the flagged items) — the only human step in the loop
engine
atoms export → manifest · compile → lattice + 12 debt ledgers → generated/
engine
per run budget-chunk: frontier gates+ranks → materializer emits scenario docs (tree + bindings + control + shrink plan + stamps)
bench
wio run executes each scenario doc: provisions the environment binding, runs atoms in their runtime, SDK streams observations
engine
oracle plane over the stream — universal tier always, declared bindings per flow — verdicts + envelopes appended to evidence/; cell states flip; reds auto-reproduce and auto-shrink (tree peel, deterministic)
skill
RED episode on anything that survives shrinking: classify · finding doc · gates. Blocked cells → named obligations. Near-misses → model hypotheses (loops back to MODEL)
human
promotes findings for filing; the board / PR check / pages render themselves from the ledger — results need no one to "report" them

Note what the arrows imply: the skill touches the pipeline at exactly two joints — before the manifest (drafting) and after the verdicts (triage). Everything between those joints is engine+bench and runs identically with the skill absent. That is the testable definition of "thin."

6Worked example: one wake of the loop

# dispatcher wakes (cron / CI / operator)
$ wio harness status --json
{ "model_debt": 0, "uncrystallized_reds": 1, "owed_cells": 212,
  "budget_remaining": "61%", "blocked": 3 }

# rule 1 fires (reds before everything) → RED episode
$ wio harness scenario queue-recover-after-ack-race --last-red
→ minimal tree: race(enqueue,enqueue) + crash@after-claim · seed 17
  control green · red-proof PASS · 3/3 seeds red · shrink log attached

# skill judgment begins: red-triager brief + source reading
→ vendor test test_queue.py:1350 asserts the cap HOLDS here → not intended
→ classification: PRODUCT · severity: correctness (w3)
# finding-writer brief → evidence/findings/dup-exec-after-claim-crash.md (draft)

# episode ends. Next wake: reds=0 → rule 3 → EXECUTE episode resumes the frontier.

Two things to notice: the agent's entire "memory" of this event is the finding file and the engine's ledger — a brand-new session next wake loses nothing; and the judgment content (the vendor-test hunt, the classification) is exactly what no function could do, which is the test that the episode boundaries are drawn right.
