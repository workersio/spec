2The seven pieces

PIECE 1The atom SDKpip / npm · ~700 LOC per language · Python + TS

Responsibility: let a product's behaviors be written as trusted, machine-readable atoms in the product's own language. The entire public API:

@flow(key="enqueue-and-complete",
      resources=(QUEUE_STATE, EXECUTOR_OWNERSHIP),   # side effects
      invariants=(EXACTLY_ONCE, ACK_NOT_LOST),       # ratified promises
      modalities=("sync", "async", "process-parallel"))
def enqueue_and_complete(ctx, queue: Queue, task: Task) -> Result:
    # inputs/outputs derived from this signature
    wf = ctx.client.enqueue(queue, task)
    ctx.checkpoint(AFTER_CLAIM)      # declaration IS emission
    return ctx.await_result(wf)

class Queue(Resource):  provision(ctx) · teardown(ctx, q)
class Task(Value):      generate(rng) · shrink = ["payload_size"]
# ctx: .client (bound handles) · .checkpoint(C) · .observe(event) — the emitter

frozen surface the decorator parameters, ctx, and the two base classes. Changes by: versioned SDK release, additive only.

PIECE 2The enginethe platform's generation service (📜 12 amendment) · ~3k LOC + ~3k tests · pure functions

Responsibility: everything mechanical about search. Seven modules, each a deterministic function — no I/O, no model calls, no judgment:

ModuleSignature (conceptually)
extractormodel package → manifest (AST/import pass; flows never execute)
validatorcomposition tree → ok | rejection-with-reason (the 12 operators' bonding rules)
compilermanifest × policy → sparse lattice: cells with states + the 12 debt ledgers; includes the engine-owned misuse negation library (state = precondition negation or flow prefix)
frontierlattice × evidence → eligible set (Stage A: debt gates), ranked (Stage B: attention as tie-break)
materializercell × seed → scenario doc (tree + bindings + auto-peeled control + shrink plan + stamps)
shrinkerred tree × re-run verdicts → minimal finding (peel operators, then declared value shrinks)
oracle planeobservation stream → verdicts, in two tiers: the universal plane runs on EVERY scenario with zero declarations — liveness horizon · terminal-state legality · undeclared-error (incl. the differential sibling mode) · resource bounds — because it checks properties of the stream itself; declared bindings (the ten invariant families) sharpen it per flow. The universal tier is the safety net: it fires even where an atom author declared nothing — gc-strand's hang is caught by it regardless of the atom's invariant list

Everything is deterministic from (manifest, policy, seed) — same inputs, byte-identical outputs, forever. Where it runs (📜 12 amendment — language public, search private): the validator ships open (with the language spec — anyone can check any composition); the compiler, frontier, materializer, sweep planner, and oracle evaluation run service-side and never ship. Generation determinism stays an internal lab invariant; only replay determinism is contractual. frozen surface none — the engine changes freely by service deploy; its outputs' formats are what freeze (§3).

PIECE 3The policyone versioned file, lives with the generation service · data, not code

Responsibility: every tunable of search, in one place, frozen ex ante per run: breadth floors · budget lanes (60/25/15) · per-cell depth caps · ranking weights · operator bounds (nesting ≤3) · load ladders · safety rails. An experiment = a diff to this file — two policies race on the same engine; the lab promotes winners. Users run the service default; power users may pin exposed overrides (their overrides are green-zone, additive-schema like everything else) — the live policy file itself never ships (📜 12 amendment).

PIECE 4The CLI: platform + harness extensiontwo release trains · one front door

Two layers, deliberately separate (the kubectl/helm, docker/compose pattern): wio proper is the platform substrate — generic, stable, anyone-can-run-anything on the bench, no atoms required, carries auth/metering. The harness client is a separately-versioned, open front-end (Python-first) that dispatches through the same front door as wio harness <verb> — it carries the language surface (SDK integration, extractor, validator, replay client) and fronts pieces 2 + 3, which run as the platform's metered generation service (📜 12 amendment: language public, search private) and iterate weekly through the lab without ever shipping a client release. The boundary between them is exactly the frozen formats: the client posts a manifest; the service returns scenario docs + debt summaries; wio hands back observations and evidence. wio never learns what an atom is; the harness never talks to a host directly.

PIECE 5The skill (plugin)skills repo → marketplace · v0.2.0 first public · thin by design

Responsibility: the judgment the loop cannot mechanize. Its SKILL.md is one operating loop:

  1. uncrystallized red? → reproduce, shrink (wio does the mechanics), triage, write the finding
  2. model stale/thin/contradicted? → re-draft atoms/resources/invariants from docs+code, with citations → critic review → user digest
  3. otherwise → wio compile, read the debt report, wio run the frontier, record friction
  4. stop when the engine says zero-debt or budget — never on a feeling

Plus its subagents: the drafting critic, the park refuter, the red triager. What it no longer contains (the v2→v3 diet): floors, weights, gates, stop rules, scenario formats — all of that moved into pieces 2–3 where a rewrite can't drop them. The skill text can be rewritten wholesale and the search behaves identically; only judgment quality changes.

PIECE 7The platformformal: convex/ + apps/web + environment · hosted, metered

Five services: the bench (managed hosts + the deterministic sim + fault injection + environment recipes + guest snapshots — where wio run executes); the generation service (pieces 2 + 3 hosted: compile · frontier · materialize · sweep-plan · oracle-eval, metered — 📜 12 amendment); the evidence service (append-only store of envelope records; the only durable harness-written truth in Convex — everything else is a rebuildable projection); the seven pages (promise board · verdict · findings · explorer · coverage&debt · release · digest — each a GROUP BY over evidence, team-scoped by origin ref, personal otherwise) plus the explain endpoint (per-project scope, probe-budgeted, fully audited — 📜 §2); the GitHub check (posts wio verdict on every PR — the adoption wedge).

Build amortization (the bench's scheduling contract): every run carries a build key = hash(target SHA · build-affecting environment fields · SDK versions). Builds are content-addressed and cached — built once, ever; guests pool warm per (build key, environment) with snapshot restore between runs. The engine's frontier stays the authority on what runs (ranked budget-chunk windows); within a window the dispatcher bins runs by build key to amortize builds — order across windows is ranked, order inside is efficiency-optimized, coverage untouched. Everything in the search space except environment (and channel's SDK runtime) shares one build: a 10–20k-run breadth pass is 1–3 builds, not thousands. Environment profiles carry a build-affecting flag (service swaps share a build; compilation flags don't). And CI verdicts accept the customer's own build artifact — their CI just built that SHA anyway; rebuilding would make the build dominate a seconds-long replay. That artifact reference rides the verdict request in the wire contract.

3The four frozen formats (the real public API)

FormatProducer → consumerCarries
Manifestextractor → compiler (and platform digest)every atom's declarations, normalized JSON, language-neutral
Scenario docmaterializer → runner (any language runtime)composition tree + bindings + control + shrink plan + model/generator/policy/seed stamps
Observation streamSDK emitter → oracle planecheckpoint-reached · effect · typed-error · terminal-state · resource counts, timestamped in virtual time

All four: versioned, additive-only, frozen more carefully than any UI or folder — they are what let every piece (and every future language SDK) evolve independently. A new language costs one SDK (piece 1); a new search strategy costs a policy diff (piece 3) or an engine PR (piece 2); neither touches the other pieces.

4One run through the whole system

  1. Draft: the skill (piece 5) reads the product's docs/code, writes atoms + resources (piece 6 green zone) against the SDK (piece 1); the user ratifies wio digest.
  2. Extract: wio atoms export → manifest (format 1).
  3. Compile: engine (piece 2) × policy (piece 3) → lattice + twelve debt ledgers → amber zone.
  4. Select: frontier gates by debt, ranks by attention → cell #1372 is owed and next.
  5. Materialize: scenario doc (format 2) with auto-peeled control and shrink plan.
  6. Execute: the bench (piece 7) provisions the environment binding, runs atoms in their runtime; the SDK streams observations (format 3); the oracle plane issues verdicts.
  7. React: red → shrinker peels to minimal; neighbors enqueue; evidence envelope (format 4) appends locally and to the platform.
  8. Surface: the board's cell flips; the PR check posts the verdict; a draft finding awaits promotion gates. Repeat from 4 until zero-debt or budget.

And what never ships

The lab — blinded corpus, blessed instruments, retrodiction, the scientist — is our apparatus for improving pieces 2, 3, and 5. Users receive promoted releases only. The lab is to this system what a wind tunnel is to an aircraft: essential, and never on the plane.
