The plan: baseline, then search

Two goals only: put the entire machine together and run it once — the baseline in the codebase — and make every search surface separately runnable. Everything after (promotion, fleet re-runs, productization, more SDKs, public release) is deliberately unplanned until the baseline exists. No dates: the factory's gates decide pace, not a calendar.

prerequisite — one, not a phase

The 📜 queue's six owed cards. The DEC codifies the contract blocks and starts the build. The factory scaffolding (§3) and eval datasets (§2) can be prepared before it lands; nothing runs against a target until it does.

1Goal 1 — the baseline: assemble everything, run it once

Build the six jobs of §3, assemble them into the full loop on the dbos fork (greenfield .workers/, self-ratified mode), and run the whole machine end-to-end once: draft → ratify-by-critic → extract → compile → gate/rank → bench → oracles → evidence → the scoreboard's first reading. The baseline is not a success metric — it is the zero point every later experiment moves from. A 0% interception baseline with honest numbers is a fine baseline.

contract · awaiting DECflagged 11 — your call

The baseline & its bar (ex-📜 item 11). Greenfield .workers/ v3 branch on the dbos fork; ~6 agent-drafted atoms + validator + debt compiler + digest; no new attention formula. The bar, all cheap: (1) both real findings' coordinates in the mandated frontier · (2) zero invalid emissions /100 · (3) retrodiction ≥ frozen attention baseline at K=20/40 · (4) policy swap → zero authored diff · (5) the gc-strand window is reachable — drafted checkpoints include parent-pending/children-complete (the one link floors can't force). Plus, for the full baseline: the loop completes on the dev slice without human intervention, and every 🔬 suite prints a number.

Fail = thesis broken for dollars: stop and rethink before anything else is built.

the two tracks — metal admission is a priced batch, never a place

Track 1 · local, three rungs: pure-local (engine · suites · retrodiction · stream-replay · toybox — zero execution) · sim-local (the DST simulator is software; only the bhyve executor needs metal) · process-local — real product as ordinary processes (DBOS + Postgres in Docker, the v0.1.3-era fault shims), i.e. how rows 1–8 actually executed: real findings at statistical-determinism grade (N reruns replace exact replay, as the shrinker already supports). The entire baseline can run here. Track 2 · metal: cells only hardware can pay (real-service/state cells, fidelity checks, the capacity canary) accumulate as a metal queue in the lattice; the frontier emits a batch manifest — frozen docs · build keys · est. runs/wall-clock/$ · debt paid — Viswa approves the number, the conductor starts the host, drains the batch, stops the host (idle-watchdog backstop). Metal never idles and never hosts exploration — local finds, metal certifies: the irreducible metal residue is contractual replay determinism (pinning officials), deterministic interleaving/instruction-preemption sweeps, snapshot economics, and fidelity/capacity numbers; envelopes stamp which substrate produced each verdict. The diff is an oracle: sim-vs-metal divergence on the same doc+seed is itself signal (ND-5's lesson; the M14 simulator-oracle comparison), so the two tracks double as a fidelity-finding channel.

3The build jobs (J1–J6) — what Goal 1 assembles

Each job = one detached Opus worker with a self-contained brief (compiled from this artifact set) and a mechanical acceptance check. J1–J3 can start in parallel; J4 needs J2+J3; J5–J6 need J4. Homes follow the resource map (🏛 Part I §5): SDK jobs in Python, engine jobs in Rust. Factory discipline: each job runs in its own sandbox — target: a container from one baked dev image (toolchain + warm build layers; repo cloned at the job's ref; per-task env: Convex deployment, config dir; cgroup CPU/mem limits), which scales to more machines by running the same image there, and converges on the bench itself as the sandbox provider once metal economics allow (Viswa's direction 2026-07-16: sandboxes, not worktrees — process/load isolation, not just code-state isolation; git worktrees acceptable only as the interim until the dev image exists); the acceptance check is a script (exit 0/1); a failing gate re-dispatches the worker with the failure output appended (bounded retries, then escalation); a passing gate merges to the integration branch and appends a ledger row. J2/J4/J5 additionally publish their golden seam fixtures (manifest → lattice → plan, dev slice at a pinned SHA) so every stage regression-tests against its neighbors' recorded outputs without running anything upstream.

4Capacity: what runs cost (measurements, not schedule)

On the fleet's r7iz.metal-16xl (32 physical cores / 64 threads · 512 GiB RAM · 3,000-IOPS gp3 root, no local NVMe), with the platform's measured numbers (VM restore ≈ ¼s/seed; cached base+deps images keep builds off the hot path):

TierScenariosRunsWall, this one host
Baselines (controls)~30–40~1.5k~13 min
Attack floor~100–150~5k~26 min
Interaction floor (coupled pairs)~40–80~2.5k~13 min
Environment matrix~30–50~1.5k~8 min
Breadth pass (all floors) — the Goal-1 run~250–350~10–15k~1–1.3 h
Every identity cell attacked once~10⁴~400k~1.5 days
CI verdict per PR (later)5–20 pinned replays~50<1 min

Sustained concurrency ~30 guests (tmpfs mandatory — 3,000 shared IOPS across 30 Postgres guests degrades 3–5×); builds 1–3 per pass, content-cached. Runs are independent and deterministic, so wall-time divides by hosts almost exactly. Caveat: the metal canary validating these numbers on real bhyve is still open.

5Later — deliberately unplanned

Promotion, fleet re-runs on real targets, the generation-service deployment split, the read surfaces, TypeScript SDK, marketplace release, public 0.2.0 — all real, all after the baseline exists and the surfaces are searchable, and none of it planned here until then. When the scoreboard has a first reading, we decide what's next from evidence, not from a phase diagram. M1/M2 (onboarding minutes incl. build spec · invariant trust) start accumulating from J3 regardless — they're S1 numbers; their product interpretation is also later.
