The search surfaces

The architecture fixed the shape by argument; six surfaces hold the values, orderings, and text that only experiments can find. Each surface gets an eval suite living in the codebase — like the determinism checks — that prints its current state on demand. Improving the system = moving one of these numbers, attributably, one change at a time.

Six of six. Why: ⚗️ the rationale · what: 🏛 the product book · reference: 📖 the spec · queue: 📜 decisions · sequencing: 🛠️ the plan. This page defines the instrument panel; the numbers live in the repo's eval output, never copied here.

The principle — decided vs. searched

Decided by design (frozen, changes by DEC): the wire formats, the bonding rules, gates-before-ranks, the openness boundary, the three zones. Searched by experiment (changes by moving a number): everything below. The instruments are ordinary test suites in formal/interception/evals — run per-commit and per-change exactly like the determinism checks — so "the lab" stops being a place and becomes a practice: every surface has a number, every number has a script, every improvement moves a number. The factory's gates consume these suites; a candidate change that doesn't move its surface's number dies without ceremony.

the floor beneath the surfaces — implementation correctness

"Is the implementation itself correct?" is not a search surface — surfaces are numbers we try to move; correctness is a floor we require to stay at zero. Its ladder, cheapest first: (1) pure-function property tests per engine module (validator rejects generated-invalid trees; compiler byte-identical from manifest × policy × seed; cell counts match independently-computed arithmetic) · (2) the golden seam fixtures (manifest → lattice → plan regression chain) · (3) determinism as a test: same doc + seed twice → identical stream and verdict; pinned reds replay red · (4) seeded faults = mutation-testing the tester: a planted bug the machine misses means a broken stage, and the testbed's key says which · (5) controls in production: a broken runner/build/oracle surfaces as control-red, classified as infrastructure, never as findings. The escape metric: harness-bug rate at triage — on the scoreboard as a floor. Structural helpers: the validator exists once (one crate in both CLI and generator), and the substrate (the hypervisor package's executor + sim) is itself a determinism apparatus.

Input construction is deliberate — four families, one principle (at small scale ground truth is computed by hand; at large scale it is planted): (1) toy manifests — 2–4-atom models isolating one behavior each, lattices small enough to enumerate on paper, tests assert exact cells · (2) generated + adversarial inputs — Arbitrary-style manifest/tree/policy generators plus mutated-invalid trees, checked by metamorphic laws (compiler output always validates; adding an atom never removes cells; every mutation rejected with the right reason) · (3) the toybox — our own tiny product with every bug planted behind a feature flag, one flag per operator × oracle-family pair: recall countable by construction, the conformance suite of the whole pipeline (evals/toybox/) · (4) frozen testbeds + recorded streams — realism, labeled keys. Plus boundary inputs: extreme policies (zero-budget, floors-only) and old-schema manifests (migration must hard-fail, never guess).

2The testbeds (the vault, decomposed)

interception/evals/
├── testbeds/                        frozen worlds the experiments run against ("environments"
│   │                                in the RL sense — named testbeds to spare the VM word)
│   └── <target>@<sha>/              ONE mountable bundle per pin:
│       ├── target/                  the product repo at the SHA (submodule ref, not vendored)
│       ├── key.yaml                 labeled bugs — severity · coordinates · repro pointers
│       ├── model/                   answer-sheet model, written FROM the key (engine evals only)
│       ├── build.spec.toml          known-good build for the pin
│       └── corpora/                 seeded-fault recipes · recorded observation streams
├── drafting/  ranking/  policy/  sweep/  vocabulary/  oracles/
└── scoreboard.py                    → one table: surface · number · trend · last change

Every suite mounts a testbed rather than owning its own data — ranking retrodicts against key.yaml, sweep replays corpora/, oracles replay the streams, and the blind-draft job mounts target/ with the key and model excluded from its sandbox: blindness is a mount option, not a separate apparatus. Testbeds are minted from fleet targets (census → label → pin SHA → answer-sheet model → freeze), so every fleet lane pays twice: live findings now, a testbed forever.

Everything above is frozen and hash-pinned — a testbed changes by PR with a version bump, never silently. Two things deliberately stay OUT of the repo: the held-out testbed (never iterated against; consulted only by the PROMOTE audit, run by the conductor — the vault's successor) and the blind-draft worker's view of any key or answer-sheet model (mount exclusion). Workers iterate in the codebase; blindness lives at its edges.

The lab decomposes into evals in the codebase (supersedes DEC-025's row loop as the iteration engine). The six surfaces above are the program's experiment inventory; each has a blessed eval suite in interception/evals/ whose numbers gate the factory. Binding rules: (1) eval suites and graders are blessed instruments — never modified by the loop they measure; changes to them are judgment-class (HELD). (2) The held-out testbed lives outside the repo, is never iterated against, and is consulted only at PROMOTE. (3) S1 drafting is graded blind — the drafting worker's sandbox excludes all keys, enforced by exclusion + transcript spot-check (DEC-012 taint rule). (4) Answer-sheet-derived models test the engine (S2–S6), never the drafting. (5) The ranking two-key rule and the random control lane are permanent. (6) The north star survives as the PROMOTE audit: blind-draft grading × held-out retrodiction × fleet outcomes; classic blinded rows are retired when the scoreboard demonstrably covers what rows measured (replacement before retirement — the scientist stays idle, not deleted, until then). (7) Fleet lanes are the continuous end-to-end instrument; maintainer responses are ground truth.
